## Architecture
- Vite + React SPA. `src/App.jsx` holds the route map, kept from the original Base44 export. Don't restructure the routes.
- `src/lib/AuthContext.jsx` is the auth provider. Its context shape (`isLoadingAuth`, `isLoadingPublicSettings`, `authError`, `navigateToLogin`, `user`, `login`, `register`, `logout`, `updateUser`) matches what the original app consumed.
- `src/api/kisanClient.js` is the **only** data access layer. It has an entity-style API (`kisan.entities.Task.list()`) plus `kisan.services.*`. It reads from `src/data/fixtures.js` and localStorage today. Backend milestones replace its internals with `fetch('/api/…')` and must keep the response shapes.
- `src/hooks/useKisanData.js` wraps the client in TanStack Query hooks. Pages use these hooks and never call the client directly, except `Assistant` and the reset button in `Settings`.
- `src/components/dashboard/*` contains the Dashboard panels. `DashboardHeader.jsx` and `AuthLayout.jsx` are original files.

- Geography: `db/geo/pakistan.mjs` is the reviewed seed for every district of Pakistan. `netlify/lib/geo.mjs` serves it in memory for `/api/geo`, `/api/weather` and the assistant (no database). To change districts or tehsils, edit the file, bump `GEO_DATASET_VERSION` and redeploy. Don't hand-write district lists anywhere else; use `useGeo*` hooks or `LocationPicker`. `src/lib/geoLocal.js` is a client-side fallback built from the same file.
- Identity: the session (`kisan-session`) holds only `{ id, email, role, onboarded }`; each email maps to a stable account id. All client data is stored per account as `kisan-data:<user_id>:<key>`; call `kisan.setActiveUser()` when the account changes. The farmer's name is `profile.display_name` (`full_name` is a legacy alias kept in sync); use `displayNameOf`/`initialsOf`/`greetingName` from `src/lib/profile.js`. Never derive a name from the email. Profile updates can't change `user_id`/`email`, and they aren't sent to the AI.
- Profile location fields: `province`, `province_id`, `division`, `division_id`, `district`, `district_id` (`"punjab/faisalabad"`), `tehsil` (name), `lat`, `lng`.

## Conventions
- Styling: Tailwind with the theme tokens in `src/index.css`. The brand palette (forest #123D2A, field #176B45, soil #101713, outline #151A17, harvest #F2C94C, alert #D94A42, cream #F5F4EC) is available as Tailwind colours (`bg-forest`, `text-harvest`, `text-alert`, …). Reuse `kisan-card`, `kisan-hero` (deep-green surface), `kisan-glass`, `kisan-chip`, `kisan-btn-primary` / `kisan-btn-gold` / `kisan-btn-ghost`, `kisan-label`, `kisan-glow`, `focus-ring`, `rise-in`, `typing-dots`, and `urdu` (Nastaliq text). Yellow = key actions/highlights, red = alerts only. Don't introduce new palettes. Fonts: Plus Jakarta Sans (body), Fraunces (display).
- Urdu/Punjabi text: set `dir="auto"` or `dir="rtl"` and add the `urdu` class.
- Theme lives in the `kisan-theme` localStorage key. Dark is the default. See `useTheme`.
- Toasts: `import { toast } from "sonner"`. `components/ui/toaster.jsx` mounts the outlet.
- Dates for tasks are local `YYYY-MM-DD` strings. Parse them with `new Date(iso + "T00:00")`.
- Shared form inputs are in `components/FormField.jsx`.

## Non-obvious decisions
- Only part of the Base44 export was available. The missing pages were rebuilt in the original design language. If the originals arrive, compare them and restore any lost behaviour without reintroducing Base44.
- shadcn `ui/` components weren't received, so the screens use plain Tailwind. Adding shadcn components is fine (`components.json` is configured).
- Voice: recording happens in the browser (MediaRecorder, `src/lib/voice.js`), speech recognition runs server-side at `/api/transcribe` (Gemini through AI Gateway), and spoken replies use browser speechSynthesis. Browser SpeechRecognition isn't used because it is unreliable for Urdu and missing in Firefox.
- Assistant: `/api/assistant` uses Claude through AI Gateway and streams NDJSON (`text`/`status`/`done`/`error`). Thinking tokens count against `max_tokens`. Effort is `low` and there's a 50 s deadline, so long answers end with `stop: max_tokens` and the UI shows "Continue answer".
- Language: `src/lib/language.js` (`detectLanguage`, `replyLanguage`) is shared by the browser and `/api/assistant`. It tells apart Urdu script, Roman Urdu, Shahmukhi/Roman Punjabi, Sindhi, Pashto and English. The assistant adds a per-turn "Reply language" note after the cached system prompt. `URDU_GUIDE` in `netlify/lib/prompt.mjs` holds the Pakistani Urdu style rules and farming glossary. Run `npm run test:language` after changing the detector, and `npm run qa:urdu` (needs `netlify dev` or `BASE_URL`) after changing prompts.
- Speech queue (`createSpeaker` in `voice.js`): keeps every utterance referenced (Chrome's GC bug otherwise drops `onend` and freezes all later replies), waits for `voicesReady()`, has a watchdog/retry, reports autoplay blocks (`onBlocked`) and `onEnd({ spoken, missing, blocked, stopped })`. Pass the reply language to `enqueue(text, { lang })` so Latin words inside an Urdu reply stay with the Urdu voice. Urdu is never handed to an English voice; with no Urdu/Hindi voice the reply stays text and the UI says so. A Hindi voice is never given Urdu script: `src/lib/urduTranslit.js` is the offline fallback when `/api/speech-text` fails. Run `npm test` (language, speech queue, profile checks) after changing these.
- Urdu speech: AI Gateway has no TTS model, so speech still uses browser speechSynthesis. `urduSpeech()` in `voice.js` rewrites ranges, units and abbreviations for spoken Urdu. When the device has no Urdu voice but has a Hindi one, `/api/speech-text` (Gemini) transliterates the Urdu words into Devanagari for the Hindi voice; it never translates. The same endpoint turns Roman Urdu into Urdu script for Urdu voices. Settings → "Urdu reply voice" / "Speaking speed" (`tts_voice`, `speech_rate`).
- Listening: `startRecording` ends a turn after `endSilenceMs` of silence (Settings → "When to stop listening": `listen_mode` auto 1.8 s / patient 3.2 s (default) / manual = until the farmer taps). Recordings run up to 5 minutes; `toWavParts` cuts them at pauses into WAV parts under a minute (the function body limit), which are transcribed in parallel and joined. Barge-in (`barge_in`, conversation mode only): while the AI speaks the mic stays open in "armed" mode, calibrated on the AI's own echo; sustained louder speech stops the speaker and that same recording becomes the next turn, trimmed to start just before the farmer spoke.
- Punjabi: `PUNJABI_GUIDE` in `prompt.mjs` (Majhi/Jhangvi/Pothohari/Saraiki grammar and rural vocabulary) is always in the system prompt. Text Punjabi is answered in Punjabi; **spoken** Punjabi is answered in Pakistani Urdu (devices have Urdu voices, almost never Pakistani Punjabi ones), and `/api/assistant` reports the reply language as `ur` for those turns. The transcriber keeps Punjabi as spoken in Shahmukhi and never converts it to Urdu.
- Scope: Kisan AI is **agriculture-only**. The "Scope: agriculture only" section of `RULES` in `netlify/lib/prompt.mjs` lists what is in and out of scope and how to decline; `languageDirective()` repeats a one-line scope reminder every turn. Don't make it a general-purpose assistant. After changing scope rules, run `npm run qa:urdu` (it includes off-topic cases).
- Removed features: mandi prices and SMS alerts are out of the product. Don't add them back.
- Auth: `AuthContext.jsx` uses Netlify Identity via `@netlify/identity` (email/password, Google via `oauthLogin('google')`, confirmation and recovery links handled by `handleAuthCallback()` on load). It falls back to local accounts when Identity isn't reachable; the demo farm is always local. Sessions carry `provider: "identity" | "local"`. Admin = Identity role `admin`.
- Farm setup: `FarmSetupGate` (wraps the Layout routes) sends a signed-in user to `/onboarding` until `missingFarmAnswers()` in `src/lib/farmSetup.js` is empty (land, water, crops/rotation, goals). `/onboarding` is full-screen, outside `Layout`. Option lists live in `src/data/fixtures.js` (`IRRIGATION_OPTIONS`, `ROTATION_OPTIONS`, `GOAL_OPTIONS`, `SOIL_OPTIONS`); call `deriveFarmFields()` before saving so `crops`/`irrigation` stay in step. `describeProfile()` in `prompt.mjs` sends the answers to the assistant; keep its `ROTATIONS`/`GOALS` labels in sync with the fixtures.
- Persistence: Netlify Database is **not available on this account's plan** (deploys fail with "database feature not available"), so don't add `netlify/database/`, `@netlify/database` or Drizzle. Use Netlify Blobs for server-side records and files until the plan changes. AI: chat runs on Gemini by default (`KISAN_CHAT_PROVIDER`=`gemini`|`claude`, `KISAN_CHAT_MODEL`); voice also uses Gemini. Spoken Urdu: `/api/tts` (Gemini speech, WAV 16 kHz) is used by `createSpeaker({ synthesize })` in `src/lib/voice.js` when the device has no native Urdu voice and no voice is chosen in Settings; on any error it falls back to device voices (Hindi voice + Devanagari via `/api/speech-text`). Create Gemini clients only through `netlify/lib/gemini.mjs` (your own `GEMINI_API_KEY` first, Netlify AI Gateway otherwise). Never hard-code keys.
